3. **Fada / فضاء الروايات (`novel.cenele`). Confirmed chapter-1 download defect.** Renegade Immortal chapter 1 has a real illustration whose primary `src` uses the legacy `riwyat.com` domain and whose published `srcset` supplies the approved `cenele.com` image. An absent `data-srcset` became an empty candidate; resolving it against the page URL produced the chapter's HTML URL. That wrong URL was selected before the valid srcset image. The pre-fix optimized Android run persisted an IMAGE block whose URL exactly equalled its chapter ID. The queue failed even on retry because the requested image was actually a text/html chapter page. Chapter 2, containing no story illustration, completed in the same batch. The legitimate image independently returned HTTP 200, image/jpeg, 376,267 bytes (1080×2321).

   `NovelContent` now discards blank srcset candidates **before** resolving URLs. It uses the real published image URL, with the same domain whitelist and image validation. Tests cover missing/blank srcsets, approved lazy/ordinary image URLs and rejected foreign-only images. Existing failed Cenele payloads can retain the wrong image in memory/disk: the existing queue now uses a narrowly scoped Cenele download helper which detects that exact impossible self-illustration, evicts only that chapter's memory entry and reparses the same saved chapter URL through the existing source. The old readable disk file remains until a successful atomic replacement. There is no guessed image URL, whole-cache reset or new downloader.

   A separate integrity defect was reproduced: halfway-cut HTTP-200 chapter HTML still produced 39 blocks/5,734 characters and could look complete. Cenele now rejects it with `CENELE_DOCUMENT_TRUNCATED`; it cannot become DONE. This injected interruption is not claimed to be an observed live server outage. Current live chapters 1, 2, 3, 13, 50 and 64 all returned HTTP 200 and parsed successfully. Chapters 1/2/3 produced respectively 107/42/48 blocks and 15,899/5,667/5,908 characters. The original phone's generic error was not captured, so not every reported failure can be attributed retrospectively to the illustration defect.
