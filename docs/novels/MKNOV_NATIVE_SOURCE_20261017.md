## العقود المثبتة

كل العمليات التالية POST JSON إلى `https://api.mknov.com/v1/`، دون حساب أو Cookie أو مفتاح خاص. تم التحقق من طلبات قراءة عامة فعلية، وليس الاعتماد على سلاسل APK فقط.

| العملية | المسار | مدخلات مثبتة | دليل التطبيق |
|---|---|---|---|
| الشائع | getWorks | works=views, limit, offset | HomeActivity.getWorksViews / MoreActivity.loadMoreWorks |
| التحديثات | latest | page | HomeActivity.getLatest |
| البحث | searchByKeyword | keyword | MoreActivity.loadMoreWorks |
| التصنيف | advancedSearch | tags[], limit, offset | MoreActivity.loadMoreWorks |
| البيانات | getWorkById | id | WorkActivity.getWorkById |
| الفهرس | getChaptersByWorkId | id عددي | ChaptersBottomdialogFragmentActivity.getChapters |
| النص | getChapterBatch | id الفصل العددي | ReadActivity.getCon |

بيانات الرد: status=success؛ الكتالوج data وtotal، البحث والتصنيفات works وtotal_works، الفهرس data على هيئة مجلدات وtotal_chapters، والقارئ data مع id وcontent وis_free.

الموقع يستخدم `/novel/{workId}` و`/novel/{workId}/chapter/{chapterId}`. هذه الروابط، لا أرقام الفصول الظاهرة، هي هويات Mangaro المستقرة. الفهرس يتطلب id عدديًا: محاولة سلسلة نصية أعادت 400؛ الطلب العددي المطابق للتطبيق نجح. لم تُتجاوز حماية أو صلاحية.

## التنفيذ والأمان

- `MknovSource.kt`: الكتالوج والبحث والبيانات والفهرس والقراءة؛ تحليل خارج الخيط الرئيسي، كاش بيانات موثقة لمدة دقيقتين، دمج الطلبات المتطابقة، وحدود ذاكرة واستجابة.
- الفهرس الرسمي كامل في طلب واحد؛ لا صفحات مخترعة ولا تنزيل أجسام فصول لبنائه. يُرتب حسب أرقام المصدر مع الحفاظ على جميع معرّفات الخادم والأجزاء والفصل صفر.
- لا تُستخدم last_chapter ولا chapter_number كعدد فصول. لا تُستخدم أوقات جلب الكاش بدل أوقات النشر.
- التحقق من انتماء الفصل للعمل قبل عرض محتواه، ومن تطابق ID الرد. is_free=false يبقى رفض وصول؛ النص الفارغ/الناقص/صفحات HTML الخطأ مرفوض.
- استخدام NovelHttp وSmart Focus وحدود الاتصالات الحالية. توسعة JSON محصورة في سبعة مسارات قراءة مثبتة، مع بقاء HTTPS وفحص الشهادات وعدم إرسال Cookies. POST لا يعاد تلقائيًا في طبقة HTTP.
- استخدام القارئ وطابور التنزيل وصيغة الملفات الحالية؛ لا قارئ/WebView/مدير تنزيل جديد.
- `NovelRepository.kt` و`NovelSourceAvailability.kt`: تسجيل المصدر المدمج. `NovelHttp.kt`: نطاق المصدر ونقل JSON المقيد. لا تعديل لتنفيذ أي مصدر قائم.
- لم تتغير NovelRules أو التوقيعات أو قوائمها الأربع أو GitHub Actions. المصدر مدمج محليًا؛ إضافته إلى الناشر مهمة لاحقة مستقلة.

## عدم التكرار واختيار الطبعة

التجميع يستخدم NovelWorkReconciler وNovelCatalogCards الحاليين. بحث الروايات يستخدم الإسقاط الموحد نفسه بدل إنشاء هويات بحث مستقلة. بحث المانهوا يستعمل هوياته الموثقة الحالية مع إصلاح تحديثات الربط واختيار عدد الفصول الفعلي.

`MknovVerifiedMetadata.kt` يحتوي حقائق علنية مدققة للمعرّفين 96 و37 فقط، لتوفير مؤلف/أسماء أصلية للبطاقات المختصرة التي لا ترسل مؤلفًا. ID 96 هو عبد الظل، Guiltythree، Shadow Slave؛ وID 37 القس المجنون، Gu Zhen Ren. بيانات التفاصيل الحية لها الأولوية. لا تُنشأ روابط فصول أو mappings سحابية بهذه الحقائق.

اختُبر اندماج عبد الظل مع طبعة SeaNovel ذات الهوية المتطابقة في عمل واحد، وبقاء طبعة لمؤلف مختلف منفصلة. اختيار الرئيسية عام: أكبر availableCount لفهرس مكتمل موثّق متاح، وليس chapterCount المعلن أو أكبر تسمية فصل. مثال الاختبار: مملكة 3218 تتقدم على طبعة تعلن 33333 ولكن لديها 10 فصول موثقة؛ تتغير الرئيسية إذا ثبت للطبعة الأخرى 4000.

تظل المكتبة والتقدم والتنزيلات بمعرّفات كل طبعة. لا حذف أو دمج سجلات مستخدمين. الأعمال غير المؤكدة لا تُدمج بتشابه العنوان أو الغلاف؛ لا ندّعي مراجعة جميع الروايات.
